# Brand Application Rules

## Purpose

This file explains how the Paanguzo brand should appear inside the product.

## Brand inside product

The product should reflect the brand through:

- confident typography
- clear structural layouts
- disciplined use of orange and black
- industrial language in key surfaces
- premium but restrained motion and atmosphere

## Logo and lockup use

The Paanguzo wordmark should feel:

- stable
- unmistakable
- architectural

Use it most strongly in:

- global nav
- footer
- hero sections
- key dashboard headers

## Tone in UI text

The product voice should feel:

- clear
- assured
- direct
- operational

It may occasionally use system-like language, but should remain readable by real users.

## Typography application

- `Sora` should carry hero headlines, dashboard mastheads, and major product moments
- `IBM Plex Sans` should carry body copy, form text, tables, and interface labels
- `IBM Plex Mono` should carry telemetry, IDs, timestamps, metrics, badges, and system language

The goal is to feel more like an infrastructure platform and less like a generic startup dashboard.

## Brand tension to balance

There is a healthy tension in this product between:

- human marketplace experience
- tactical command-center experience

The UI should balance both:

- public pages can feel more aspirational and expansive
- operational pages should feel more precise and instrument-like

## Where to push the brand harder

- navigation
- hero sections
- dashboard headers
- stat cards
- key call-to-action buttons
- modal headers
- empty states
- loading states
- notification toasts
- section headers

## Where to keep the brand quieter

- long tables
- dense form areas
- utility screens
- admin maintenance screens

## Visual consistency rules

- one page should not mix soft fintech styling with industrial styling
- one workflow should not switch button personality mid-flow
- badge meanings should stay stable across the app
- orange should remain special and directional
- loading, empty, and success states should feel like part of the product system
- operational screens should use repeatable shell patterns, not one-off compositions

## Brand UX patterns

The brand must appear in reusable product patterns, not only in colors or hero styling.

- dashboard shell
  dark side rail, strong masthead, quick stats, framed work area
- section shell
  eyebrow, title, short operational meta line, action zone
- empty state
  mono label, compact glyph, clear action-oriented explanation
- loading state
  restrained indicator, structural framing, concise status label
- notification toast
  framed card, semantic rail, mono time, short operational message
- table shell
  dark head, quiet rows, strong numeric alignment, restrained accents

## Copy behavior

- public pages can be more expansive
- dashboards should be direct and operational
- labels should prefer precise verbs over generic software copy
- system-style language should support clarity, not obscure it

## Brand application test

When reviewing a screen, ask:

1. Does this feel like Paanguzo, or like a generic template?
2. Is the visual hierarchy disciplined?
3. Is orange being used purposefully?
4. Does the page feel more like infrastructure and operations than consumer fluff?
5. Would this still feel premium if the motion were removed?

If the answer to the last question is no, the styling is too effect-dependent.
