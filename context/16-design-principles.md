# Design Principles

## Purpose

This file defines the visual principles the platform should follow so future UI work remains cohesive.

## Core visual direction

The product should feel:

- industrial
- precise
- operational
- premium
- trustworthy
- globally ambitious

It should not feel:

- generic SaaS
- playful consumer startup
- overly glossy
- excessively futuristic
- crowded or noisy

## Design character

The platform is strongest when it looks like:

- an infrastructure operating system
- a marketplace for serious procurement and execution
- a command surface for logistics, projects, contracts, and capital

## Typography rules

### Display type

Use `Space Grotesk` for:

- hero titles
- page titles
- major section headings
- high-importance emphasis blocks

Do not use it for long body copy or dense operational tables.

### Body type

Use `Inter` for:

- paragraphs
- forms
- descriptive labels
- normal navigation copy
- dashboard body content

### Mono type

Use `JetBrains Mono` for:

- system labels
- IDs
- telemetry
- badge text
- status strips
- metadata
- control surfaces and operational copy

Mono should signal precision, not overwhelm the interface.

## Color rules

### Base palette

Primary product colors:

- foundation black
- structural steel
- limestone white
- earth orange

### Reserved accents

- copper = finance or capital
- steel blue = system or informational state
- savanna green = positive or healthy state
- african violet = innovation, AI, advanced intelligence
- danger red = destructive or error states only

### Usage rules

- most surfaces should stay neutral
- orange should be meaningful, not everywhere
- avoid too many competing accent colors within one screen
- use color for hierarchy and state, not decoration alone

## Surface rules

- use bordered panels generously
- use mild blur sparingly
- preserve strong legibility
- prefer structured panel framing over soft “floating app” aesthetics
- shadows should support depth, not dominate the screen

## Motion rules

- use motion to reinforce structure and intent
- hover effects should feel controlled and mechanical
- avoid excessive bounce on dense operational screens
- page transitions should be subtle
- focus states must stay obvious and accessible

## Content density rules

- dashboards can be information-dense, but hierarchy must stay clear
- marketplace cards should feel premium but scannable
- tables should prioritize readability over ornament
- empty states should feel intentional, not unfinished

## What to avoid

- uncontrolled variant growth
- one-off gradients in random components
- inconsistent badge logic
- oversized blur/glow everywhere
- mixing three or four visual metaphors on one page
- default-looking forms next to premium shells
